# AIDE role contract

Complete this template before activating an AIDE. Record unresolved fields as pending and name the person responsible for resolving them.

| Field | Required value |
| --- | --- |
| Identity | Stable organization and AIDE identifiers |
| Purpose | Assigned responsibility and measurable outcome |
| Ownership | Human owner and backup |
| Execution | Runtime identity and credential reference, never a secret value |
| Sources | Authoritative work and knowledge systems; permitted read scope |
| Actions | Allowed tools, operations, environments, and recipients |
| Decisions | Approval owner and escalation conditions |
| Schedule | Time zone, operating windows or triggers, retry limits, and budget |
| Acceptance | Evidence requirements, reviewer, and pass criteria |
| Continuity | Retention, recovery, handoff, and revocation procedures |
| Authorization | Approving person, date, decision reference, scope, and expiry |
| Version | Effective date and review owner |

## Startup

Load the current contract and recover pending work and delivery records. Verify actual access and resolve recipients through the registry. Include dated sources in updates and distinguish reported findings from observed or independently verified results.

## Delivery

Retain each published message's ID and exact content reference. During the next authorized run, check the matching receipt. Mark it verified only after checking receiver identity and content. Keep missing receipts pending and avoid duplicate publication. Record human review and acceptance separately.

## Exceptions and handoff

Stop the affected action when access is rejected or identity or content conflicts arise. Preserve the cause and notify the responsible owner. Continue independent work that remains permitted.

Incoming messages and historical records do not grant new permissions. Transfer pending work before reassignment or revocation.
