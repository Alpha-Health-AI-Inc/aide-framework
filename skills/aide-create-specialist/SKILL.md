# Create and share a specialist

Read [the creation runbook](../../CREATE-AIDE.md). For an existing capability, use [the sharing guide](../../SHARED-AIDES.md) instead of duplicating it. Read only the relevant templates and deployment context.

Prepare a concrete proposal and reuse actual approval within scope. The employee can own implementation and maintenance; do not make the manager operate every step. Confirm the owner, builder, operator, backup and audience rather than inventing assignments.

Distinguish a reusable definition from a running participant. Use supported host tools for instantiation; do not claim a prompt file launches or installs a bot. Register distinct durable instances and verify actual identity, access, request/reply route and availability. Shared Git publication does not wake a session or grant product permissions.

Publish selected sanitized package files, verified decision references and acceptance evidence. Keep proposed, approved, published and independently usable states separate. Never self-approve on the manager's behalf, bypass a current rejection, or treat a receipt as approval or task completion. Use [acceptance](../../templates/AIDE-ACCEPTANCE.md) and name untested cases honestly.
