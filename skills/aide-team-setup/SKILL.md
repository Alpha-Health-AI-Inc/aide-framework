# Team setup

First execute [Git-first onboarding](../../GIT-FIRST.md). Verify the actual account and destination before substantive file generation. Reuse answers already supplied; employee assignments can be gathered by their own agents later. Do not fabricate team policy or reporting lines.

Read [the manager setup runbook](../../AGENT-SETUP.md) and [template mapping](../../templates/README.md). Execute the runbook using the host's available, authorized filesystem and Git tools. Read provider guidance only for the chosen route.

Prepare defaults and actual local files before presenting the manager with publication or access decisions. Reuse existing approval within scope. Ask compactly for only essential missing facts; never infer organization identities from the public upstream.

Resume existing setup state and inspect remote evidence before repeating mutations. Do not replace participant IDs, erase local work, lower branch protections or route around permission rejection. Record blocked operations and their exact causes.

Keep prepared, published, employee connected, first handoff verified and human accepted as separate states. Use [setup acceptance](../../SETUP-ACCEPTANCE.md); report real artifact references, not a generic success statement. A counterpart that has not run remains pending.
